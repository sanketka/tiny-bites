# Baby Breakfast Bot

Sends a daily Telegram message with a breakfast recipe for your child. Recipes are generated by Claude Haiku based on what's in the pantry. Scheduled via GitHub Actions.

## What Each File Does

- `send_breakfast.py` -- main script: loads pantry + config, calls Claude, sends Telegram message, logs recipe
- `config.toml` -- all user settings: child info, location, cuisine, schedule, allergies. Thorough comments explain each field.
- `pantry.txt` -- source of truth for what's stocked at home. Edit this when groceries change, push to update.
- `recipe_log.json` -- auto-updated by GitHub Actions after each run. Tracks last 7 recipes to avoid repeats. Do not edit manually.
- `setup_bot.py` -- interactive onboarding CLI. Run once after forking to configure everything. Also supports `--update-schedule` for DST changes.
- `backlog.md` -- improvements log. Add to this when new ideas come up.
- `.github/workflows/daily_breakfast.yml` -- cron job. Generated by setup_bot.py with the correct UTC time for your timezone.

## Nutrition Priorities

Configurable in config.toml. Default: protein first, then fiber. Recipes are tailored to the child's age (calculated from birthday): soft textures, no honey, no choking hazards, low sodium.

## How to Test

Trigger manually from GitHub Actions tab, or via CLI:
```bash
gh workflow run daily_breakfast.yml
```

## Key Gotchas

- `recipe_log.json` is committed back to the repo by the GitHub Action after each run. Always `git pull --rebase` before pushing to avoid conflicts.
- DST: GitHub Actions cron is UTC. After clocks change, run `python setup_bot.py --update-schedule` to recalculate, then commit and push.
- Pantry and config are read fresh at runtime. No code changes needed for routine updates.
- Model: Claude Haiku 4.5. Sufficient for this use case.
